# 资料录入约定

## 人工资料

在 `data/glyph-notes.json` 里以字形文件夹名为键补充资料。最小记录可以只补一项释义和审核状态：

```json
{
  "07467_八_Z_說文‧八部": {
    "definition": "释义文字。请在拉取请求说明引用的文献版本。",
    "formation": "构形说明；未确认时请明确写待核。",
    "components": [
      { "name": "部件名称", "kind": "部件类型", "status": "已核" }
    ],
    "reviewStatus": "已核对 2026-08-05"
  }
}
```

`components` 为空时，网页会明确提示“尚未登记人工部件”，不会把算法笔段伪装成传统部件。

## 新实验

- 确保实验根目录包含 `summary.json`。
- 每一个字形文件夹都应有 `result.json`、各类 PNG 和 `strokes_individual/`。
- 导入后检查 `data/glyphs.js` 的字数与 `summary.json` 一致。
- 提交图片前留意仓库大小；若未来样本量很大，可将实验图改放 Git LFS 或对象存储，但资料 JSON 和缩略图仍应留在主仓库。

## 提交建议

- 每个拉取请求尽量只做一类事情：资料校释、算法结果导入、关系规则或界面改动。
- 不要顺手格式化生成文件之外的无关内容。
- 涉及释义或构形结论时，在拉取请求描述里附文献出处和不确定性说明。
