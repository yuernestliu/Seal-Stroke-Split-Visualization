# GitHub Pages 发布

本项目是静态站点，不需要服务器后端、Python分析环境或npm前端构建。根目录index.html为入口，资源使用相对路径，可部署到GitHub项目子路径。

## 当前状态

2026-10-21检查：yuernestliu/Seal-Stroke-Split-Visualization的GitHub API返回has_pages:false。本地已准备发布配置，但尚未启用Pages、提交推送或运行线上部署。不能把预定网址称为已上线网址。

## 首次发布

1. 在Ernest仓库 Settings → Pages → Build and deployment，将Source设为 **GitHub Actions**。
2. 将本地整合后的源码、字库、资料、README和本次发布配置提交并推送到main。
3. 查看Actions里的 **Publish static website**。工作流会检查脚本、构造_site目录，再发布GitHub Pages；也可通过Run workflow手动触发。
4. 等deploy任务成功，再检查下列网站、安字拆合、500字库和学生计划入口。

- 网站：https://yuernestliu.github.io/Seal-Stroke-Split-Visualization/
- 学生计划：https://yuernestliu.github.io/Seal-Stroke-Split-Visualization/plan.html
- 不依赖Pages的学生计划：[项目计划.md](项目计划.md)，GitHub仓库README顶部也可进入。

后续推送main会自动更新网站。仓库README是所有资料入口；网站上的plan.html给学生展示当前首要任务与后续路线。

## 本地检查与打包

```sh
npm run check
npm test
npm run build:pages
```

scripts/build_pages.py只把网页运行目录复制到_site，研究资料、历史页面和node_modules不进入发布产物。它逐层跳过禁止名称和符号链接；已有输出目录不会被自动清空，重新打包请先自行保存／移走旧产物或传入新的--output目录。_site已加入.gitignore。

工作流使用稀疏检出，只取网页源文件；打包后上传_site。完整研究资料仍在GitHub仓库中，通过README访问；不需要把研究目录作为公开网页资源上传。

官方参考：[GitHub Pages自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
