# 学生 To-Do Plan：先完成500字的高质量字形与骨架

> **当前首要任务：把候选集的500字全部处理到可复核、可复用。** 不以“原图已经下载”“扩展名变成SVG”或“包在SVG里的PNG”作为完成标准。先确认10个示范样本的质量，再分批覆盖全部500字。

## 首要任务与交付物

每个字保留完整字形ID，至少交付：

1. 原图及来源；保留未经修改的原件。
2. 清理后的字形掩膜：去除毛边和噪声，记录人工修补及参数，不能随意改变连通、孔洞、交叉和细笔。
3. 高质量轮廓SVG：真正的矢量路径，和原图有明确坐标对应；不能只给SVG嵌入位图。
4. 骨架与拓扑记录：节点、边、曲线采样／拟合、闭环、必要的宽度与坐标映射，能叠回原图核对。
5. 复核记录：原图／清理图／轮廓／骨架的叠加对比、已知歧义、负责人和复核人；不能只写“看起来更光滑”。

建议按 `字库/处理结果/<完整字形ID>/` 组织，约定见 [处理结果规范](../字库/处理结果/README.md)。现有四字的严格平滑结果仍以data/cleaned-glyphs为准，先引用而不复制另一份几何。

整体顺序：**原图 → 清理掩膜 → 轮廓SVG与骨架图 → 组成单元及结构关系 → 梯径输入编码 → 分析**。轮廓主要服务展示，规范骨架图是形体／结构分析的共同几何入口。骨架不自动给出真实笔画、笔顺或古文字构形；故事和文献整理可以同时进行，不必等待骨架完成。

完成门槛：500字均有可读结果和逐字复核状态；无法判断的地方有明确待核标记，不能自动伪装为已确认结构。现有cleaned-glyph生成器依赖已知笔段，只适用于已有这类数据的字，不是剩余500字的自动处理器。

## 愿景与起点

一个本科生愿意打开、拆一拆、继续看下一个字的小篆界面：字形可拆合，故事有出处，联系有依据。最终希望用梯径组织结构关系，目前先用可追溯的偏旁部首／IDS先验。

2026-10-21：统一原图14,120张（14,112大库 + 8张原实验独有样本）；原有124字有轮廓SVG及笔段，61字有释读；严格平滑并完成显示核对的仅安、宇、包、光4字。**没有完成500字的SVG平滑。** 轮廓SVG、平滑笔段SVG、用SVG嵌入PNG蒙版是三种不同状态。

新增458字模板全部待核：181字只有1个颜色分区，276字2个，1字3个。颜色分区不是书写笔顺或已经确认的构件。500候选集中当前有18字轮廓／笔段资料、3字严格平滑、12字模板、18字释读，其余尚待逐字推进。

用本项目已有BCC多领域字频（2026-05-27来源快照），按频率排序，只取单个汉字；优先同字匹配，必要时使用OpenCC单字简繁候选，记录歧义与待核状态。从可匹配且字形ID不重复的记录中选满500／2000，500为2000子集。

这是项目试跑候选集，不是官方标准，也不是原字频Top500／Top2000的完整复刻。原Top500缺20字，候选500截止第521位；原Top2000缺184字，候选2000截止第2215位。缺字独立保留，不自动补造。简繁匹配不构成古文字字源判断。

## 学生怎么分工

- 字形组：模块/字形展示/。负责原图、轮廓、平滑笔段与候选部件；逐字结果放data/cleaned-glyphs/。
- 故事组：模块/字源故事/。负责短故事、文献、历史节点与展示，不改算法。
- 关系组：模块/字间关系/。负责纯规则、关系图、梯径适配，不把分类写死在绘图逻辑中。

每次认领5—20字，填写 `字库/字表/500字任务表.csv` 中负责人、复核人、备注。先交小样，核对后扩批。自动结果先为draft／candidate；经复核再升级。生成器保留任务表内已有分工，但详细结论仍应落在逐字JSON和来源记录中。

## 梯径可以先用组成单元

可以不先恢复传统笔画。第一条路线用经核对的部件／构件为先验；第二条路线用跨字归一化的几何片段或骨架子图。单元必须在不同字中可识别、可复用，且保留组合关系。字源构件、图像连通块、骨架边和书写笔画不是同一个概念。

例如“安”的分析方案可记为 `上下(宀,女)`，“林”可记为 `左右(木,木)`：这是待核对的结构编码示意，不是已经运行的梯径结果。相同部件用相同符号，但不能只取部件集合而丢掉排列。跨字形态差异、旋转／镜像是否视为同类，都要先定规则。

现有 [lppack](https://github.com/yuernestliu/lppack) 是序列接口。二维组成关系需先定义可复现的编码或另做图结构扩展，不能声称库已经直接支持任意骨架图。若把结构树线性化，应固定遍历、边界与单元字典，并检查括号、结构符号、标签拼写造成的人工重复；单元ID宜映射成单个不可再拆的符号。不同基元、组合操作和成本的结果不能直接当作同一种度量比较。

建议先做一组人工核对的小样：部首／IDS方案作为基线，骨架子图方案作为后续几何路线，再比较哪些共同结构确实来自字形，而不是来自编码。方法依据：[梯径原始论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC9407278/)，上述小篆适配是本项目待验证的方案。
