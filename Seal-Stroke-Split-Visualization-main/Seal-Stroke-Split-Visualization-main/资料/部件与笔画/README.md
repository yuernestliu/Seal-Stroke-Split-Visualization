## 现在已怎样使用

scripts/build_component_priors.py将CSV中与500候选ID对应的记录，转为字库/部件候选/500字候选.json和先验索引.js。每条带来源、method、candidate_needs_review、confirmed:false及not_pixel_alignment。故事区域在无人工构件时可显示这些候选，不把它们升级为形旁／声旁或已核切分。

模板界面与原有字形兼容：笔段拆分和平滑四字保持原几何；新模板显示“拆部件”；只有原图的字标为待完成。缺少笔段的字不以伪零值参与几何相似度。

## 学生下一步怎么用

1. 先选500候选中的10字，在CSV找对应ID并看模板结果。
2. 对照原图，标出候选部件实际包含哪些像素／笔段；记录不匹配与歧义。
3. 名称、像素、传统构形、书写笔顺分别核对；一个成立不代表其余成立。
4. 笔段／部件表示稳定后再定义梯径编码，比较梯径与先验分类。

## 暂时不要直接做的事

原脚本中有Windows绝对路径、按部首分类等未随当前仓库提交的输入目录，以及与网页458字来源不同的实验路径。它们仅归档为资料，本次没有运行。移植时先限定输入与输出到允许目录，禁止跟随符号链接，逐层跳过任何_FORBIDDEN_前缀路径，再在小样本复现。不要对全库直接rglob。

不要直接重跑原build_template_parts.py覆盖现有458字；先明确源彩色模板批次与像素规则，再输出新版本。不要把14,158条实验记录、14,120张统一原图、582条带流程记录当作同一统计口径。
